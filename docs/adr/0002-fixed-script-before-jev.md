# 手順が毎回同じ作業は固定のスクリプトで行い、Jev のツールは保留する

当初の目標は、TypeSafe の Jev で 1 手ごとの判断を速くし、ウェブ操作を高速化することだった。
しかし最初の具体的な用途（決まった掲示板の新着を定期的に確認する）は、手順が毎回同じである。
そのため、モデルを使わない固定のスクリプトのほうが速く、読み取りしかしないことをコードで確かめられる。
固定のスクリプトは保存済みスクリプトとして実行する（ADR 0003）。
Jev のツールは、手順が毎回変わる具体的な作業が出てくるまで作らない。使う作業がなければ、実際のサイトで速さも判定の正しさも測れないためである。

## 保留した Jev のツールについて決めたこと

作るときは次の形にする。手本は browser-use の jev-ultrafast とする。
Jev のツールはどのサイトにも使える汎用のものなので、ego-lite に置く。

- 中身が固定された独立の MCP ツールにする（ADR 0001）。
- 当面は読み取り操作だけを扱う。判定は二重化する。1 段目では、書き込み操作になりうる要素を Jev に渡す候補から除く。2 段目では、記録を変える通信（POST・PUT・DELETE・PATCH）を止め、止めた時点でループを停止して報告する。どちらの段もモデルを使わない。
- 入力欄に書く値は、jev-ultrafast のように文章生成モデルに書かせるのではなく、Claude が目標と一緒に先に渡す。足りなければ停止して Claude に戻す。
- 終了時には、最終ページの内容、終了理由、操作の履歴を返す。

未確認の点：2 段目の通信の遮断が `page.cdp()` と `page.events()` で実現できるか。読み取りに POST を使うサイトで誤って止めないか。

## 今後の課題

- 操作の分類を、コーディングエージェント pi の 4 つの道具（read / write / edit / bash）にならって細かくする。
- Jev に、操作が読み取り操作かどうかの判定と、目標が達成されたかの検証をさせる。操作を選ぶ問い合わせとは別の問いとして、選択の形で尋ねる。二重化の代わりにはせず、その上に重ねる。
