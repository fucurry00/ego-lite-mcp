# 固定の作業は保存済みスクリプトとして名前で実行する

ego-lite に、`~/.config/ego-lite-mcp/scripts/<名前>.js` を実行するツールを足す。このツールは引数に名前だけを取る。
ADR 0001 の「常に許可にするのは中身が固定されたツールだけ」を、作業ごとに MCP サーバやツールを足さずに満たすためである。
サイトに依存するスクリプト（どの掲示板を見ているかなど）はリポジトリの外に置くので、公開リポジトリには利用者個人の情報が入らない。
`ego-browser nodejs` は Node.js そのもので、`node:fs` で手元のファイルを読み書きできる。そのため、既知の投稿の記録のような状態も、スクリプト自身が持てる。ego-lite はスクリプトの中身を知らなくてよい。

スクリプトを書く場所は、非公開の git リポジトリとする。Claude もそこで自由に書ける。
書く場所から実行用の場所へのコピー（配置）を利用者が承認し、その時点で中身を確認する。
確認は、実行のたびではなく配置のときに 1 回だけ入る。

## 採らなかった案

- **個人用の別の MCP サーバ**：`server.mjs` の起動・時間切れ・出力上限・エラー文言の処理を写すことになる。
- **ego-lite に告知確認のツールを直接置く**：公開リポジトリに個人の監視先が入る。
- **ego-lite が非公開リポジトリのスクリプトを直接実行する**：Claude が書き換えたスクリプトが、確認を経ずに常に許可のツールで実行される。
- **`~/.ego` の中に置く**：ego lite 本体のデータ置き場（`secrets/` や `state.sqlite` がある）で、本体の更新で消えたり上書きされたりするおそれがある。

## 帰結

- 常に許可の対象はこのツール 1 本なので、実行用の場所にあるすべてのスクリプトがまとめて確認なしで動く。そこに読み取り専用のスクリプトしか置かないことは、コードでは強制されず、利用者の運用で守る。
- 配置の関門は、Claude Code が作業ディレクトリの外への書き込みに承認を求めることに頼っている。自動モードでもこの承認が出るかは未確認である。出ない場合は、実行用の場所への書き込みを許可ルールで「確認する」に設定する。
- `ego_run_script` は、ブラウザ操作に加えて手元のファイル操作と外部への通信ができる。pi の `bash` に相当するので、「その都度確認」に戻す。
